（1）设计差异：

O(1) ：本质是基于优先级的多级反馈队列。通过为每个 CPU 维护两个数组（Active 和 Expired），每个数组包含 140 个优先级队列。它根据进程的静态优先级和启发式估算的“互动性”动态调整优先级，分配固定的时间片。当 Active 数组任务运行完，交换两个数组。

CFS ：放弃了固定时间片的概念，引入了虚拟运行时间 。它通过一棵红黑树维护就绪进程，红黑树的键值即为虚拟运行时间。调度器总是选择树中最左侧（虚拟运行时间最小）的任务运行。任务运行后，其虚拟运行时间增加，增加速度与权重（由 Priority 映射）成反比。



（2）是后者。

在无限小的时间轴上，每个进程按权重比例获取 CPU 时间。

由于上下文切换有代价（Cache 失效、寄存器保存），不能无限切分。

目标延迟：保证所有任务在 6ms 内至少跑一次。

最小粒度：防止因任务过多导致每个任务跑的时间太短而被频繁切出。

这是一种针对现代交互式负载优化的工程近似公平而非绝对数学公平。

（3）在极大规模进程且任务类型极其均衡的服务器负载下，O(1) 可能更优，此时CFS 插入/删除任务的时间复杂度是 $O(\log N)$，而 O(1) 始终是 $O(1)$。当 $N$ 极大时，红黑树的维护开销（树旋转、缓存不命中）会显著增加调度本身的 CPU 占用。

（4）CFS 消除了 O(1) 中复杂的启发式优先级升降算法（那个算法导致了不可预测的交互行为），从架构上更简洁。但它并未完全通过算法消除启发式，而是将参数收敛到了几个关键阈值上。
在 Big.LITTLE（异构） 架构下，CFS 的公平定义失效，因为“1ms 的大核时间”不等于“1ms 的小核时间”。这导致了 EAS (Energy Aware Scheduling) 的出现，将“算力(Capacity)”引入公平公式。

（2）调度器周期性地检查调度域，计算各 CPU 的负载贡献。若某队列负载显著高于平均值，则触发“拉取（Pull）”操作，将进程从忙核迁移到闲核。

代价：
1.  缓存冷启动：进程迁移后，其原有的 L1/L2 缓存数据失效。
2.  TLB Flush：跨核迁移增加地址转换开销。
3.  锁竞争：操作其他 CPU 的 Runqueue 时需加锁。

权衡：利用 `SD_BALANCE_WAKE` 等标志，只有当负载失衡超过一定阈值（通常是个百分比）时才迁移，以保证迁移收益大于性能惩罚。

**1. 可剥夺优先级调度（Static Priority Preemptive）**
*   **顺序**：时刻检查就绪队列中优先级最高的进程。若新到达进程优先级高于当前，立即抢占。
*   **周转时间 (TAT)** = 完成时间 - 到达时间。
*   **带权周转时间 (WTAT)** = TAT / 实际运行时间。

**2. 基于优先级的时间片轮转（Priority + RR）**
*   **规则**：
    *   同一优先级任务间：按 RR 分配 2ms。
    *   不同优先级间：通常高优先级全跑完才跑低优先级，或者高优先级分配更多时间片。根据题目要求“统一恢复 2ms”，通常指在同一优先级层级内的轮转。
*   **计算关键**：记录每个时刻任务的剩余时间及其在队列中的位置。

（1）是。如果网络中断频率过高，CPU 会被中断处理程序及其相关的 SoftIRQ完全占据。由于中断优先级高于任何用户进程，用户进程将无法获得 CPU，表现为系统响应断绝。

解决：混合中断与轮询。当数据包到达时触发中断，中断程序关闭中断并通知内核进入“轮询模式”。内核在一个专门的时间片内批量读取数据包。当包处理完，再重新开启中断。这保护了系统不被频繁的中断打碎采样时间。

（2）优势情况：缓存隔离：其他核心（CPU1-3）的缓存（L1/L2）不会被中断处理程序的代码和数据污染，适合计算密集型任务。确定性：减少了任务执行的抖动（Jitter）。

劣势情况：
1.  性能瓶颈：如果 IO 负载极重，CPU0 会成为单核瓶颈，导致处理延迟增加。
2.  响应不均：CPU0 上的进程（如系统关键任务）会被严重拖累。

权衡结论：对于延迟敏感、计算密集的实时系统，建议绑定（甚至隔离隔离核）；对于高并发、吞吐导向的 Web 服务器，应开启 `irqbalance` 让中断在全核分布以利用多核带宽。
